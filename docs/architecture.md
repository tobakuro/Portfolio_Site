# アーキテクチャ

---

## 全体構成

```
ユーザー
  │
  ▼
Cloudflare Pages        # フロントエンドホスティング (CDN込み)
  │  静的HTML/CSS/JS (SSG)
  │  ビルド時にMarkdownコンテンツを埋め込み済み
  │
  │  動的データ取得 (fetch)
  ▼
Fly.io                  # Go REST APIサーバー
  │
  ├─ GitHub API プロキシ  # 最近のコミット・リポジトリ情報
  └─ お問い合わせ受信     # (将来対応)
```

## 使用技術スタック

### フロントエンド

| 技術 | バージョン | 用途 |
|------|-----------|------|
| Astro | 6.x | SSGフレームワーク、コンテンツ管理 |
| React | 19.x | インタラクティブなUIコンポーネント |
| TypeScript | 5.x | 型安全な開発 |

### バックエンド

| 技術 | バージョン | 用途 |
|------|-----------|------|
| Go | 1.26.x | REST APIサーバー |

### コンテンツ管理

| 技術 | 用途 |
|------|------|
| Markdown + YAML frontmatter | 成果物・ニュース等の静的コンテンツ管理 |
| Astro Content Collections | Markdownの型安全な読み込み |

### インフラ

| サービス | 用途 |
|---------|------|
| Cloudflare Pages | フロントエンドのホスティング・CDN |

### 開発環境

| ツール | 用途 |

## データフロー

### 静的コンテンツ（自己紹介・成果物・ニュース）

```
Markdown/YAMLファイル (content/)
  └─ Astro ビルド時に読み込み
       └─ 静的HTMLとして出力 → Cloudflare Pages
```

### 動的コンテンツ（GitHub情報）

```
ブラウザ → Fly.io (Go API) → GitHub API
              └─ レスポンスをブラウザに返却
```

Goを経由することでGitHub APIトークンをフロントに露出させずに済む。

---

## 設計方針

- **静的優先**: コンテンツはビルド時に解決し、ランタイムのAPIコールを最小化
- **軽量**: Reactはインタラクティブな箇所（Island Architecture）にのみ使用
- **更新容易性**: 成果物・ニュースはMarkdownファイルの編集のみで更新可能
